# Handwritten Text Recognition with TrOCR

A transformer-based handwritten text recognition (HTR) pipeline for converting handwritten line images into text using Microsoft's TrOCR architecture.

> **Project status:** Experimental research/learning project. The current experiment uses model-generated pseudo-labels, so its metrics should be interpreted differently from a conventional supervised HTR benchmark.

## What this project does

The system accepts a handwritten line image and generates a text transcription.

**Pipeline**

```
Handwritten image
       │
       ▼
Image validation & preprocessing
       │
       ▼
Data augmentation (training)
       │
       ▼
TrOCR vision encoder-decoder
       │
       ▼
Text generation
       │
       ├── Beam-search decoding
       ▼
Optional spell correction
       │
       ▼
Final transcription
```

## Model

- **Base model:** `microsoft/trocr-base-handwritten`
- **Architecture:** Vision Encoder-Decoder Transformer
- **Framework:** PyTorch + Hugging Face Transformers
- **Generation:** configurable decoding, including beam search
- **Model size:** approximately 334M parameters

## Dataset

The experiment uses a local subset of **4,899 IAM handwriting line images**.

The dataset itself is **not included in this repository**.

## Important experimental detail: pseudo-labeling

The local image files used for this experiment did not contain transcription labels. To make the fine-tuning pipeline executable, the pretrained TrOCR model was first used to generate text predictions, which were then treated as pseudo-labels.

Therefore:

```
image → pretrained TrOCR → pseudo-label → fine-tuned TrOCR
```

This is an experimental pseudo-labeling workflow. The recorded validation metrics **must not be presented as equivalent to a standard supervised IAM benchmark using independently verified ground-truth transcriptions**.

A planned next iteration is to use verified IAM transcriptions and an untouched test split.

## Engineering features

- CUDA/GPU detection with CPU fallback
- FP16 mixed-precision training when CUDA is available
- Gradient checkpointing
- Data augmentation:
  - small rotations
  - Gaussian blur
  - brightness/contrast variation
  - small translations
- Checkpointing every 500 steps
- Resume-from-checkpoint support
- Cosine learning-rate schedule
- Warm-up and weight decay
- CER, WER and exact-match evaluation
- Beam-search inference
- Optional dictionary-based spell correction
- Single-image inference function

## Recorded experiment

| Metric | Result |
|---|---:|
| Character Error Rate (CER) | **3.01%** |
| Word Error Rate (WER) | **7.33%** |
| Exact Match | **67.55%** |

These values belong to the **pseudo-label experiment described above** and should be interpreted in that context.

## Getting started

### 1. Clone

```bash
git clone https://github.com/OmBarvaliya12/handwritten-text-recognition-trocr.git
cd handwritten-text-recognition-trocr
```

### 2. Create an environment

Python 3.10+ is recommended.

```bash
python -m venv .venv
```

Windows:

```powershell
.venv\\Scripts\\activate
```

Linux/macOS:

```bash
source .venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

For GPU training, install a CUDA-compatible PyTorch build appropriate for your machine.

### 4. Prepare the data

Place the local IAM line-image subset in `data_subset/`.

The notebook also expects the metadata file used by the experiment: `forms_for_parsing.txt`.

These files are intentionally excluded from Git.

### 5. Run the notebook

Open `notebooks/HTR_TrOCR_System.ipynb`.

The notebook walks through environment setup, dataset inspection, image validation, TrOCR loading, pseudo-label generation, augmentation, dataset preparation, training, evaluation, inference, and optional spell correction.

## Inference

After loading the model and processor:

```python
prediction = predict("path/to/handwritten_image.png")
print(prediction)
```

## Limitations

1. Current training labels are generated by the pretrained TrOCR model rather than independently verified transcriptions.
2. The validation metrics therefore do not establish a conventional supervised benchmark result.
3. The current split is a random 90/10 split; a writer-aware split should be considered for stronger HTR evaluation.
4. No production API or web deployment is included yet.
5. The spell-correction component is a lightweight dictionary-based post-processing experiment.
